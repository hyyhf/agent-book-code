# 文件编辑工具：用法、性能与边界

2026-09-29 升级。保留 `tool_replace_in_file` 名称、单次 old_text/new_text 调用和批量 replacements；文本读取、写入、编辑共享 `core/file_editing.py`。

## 高频编辑用法

先读取需要的代码窗口：

```json
{"path":"src/example.py","start_line":80,"limit":100}
```

同文件的独立改动放在一次 `tool_replace_in_file` 调用中：

```json
{
  "path":"src/example.py",
  "replacements":[
    {"old_text":"timeout = 300","new_text":"timeout = 900"},
    {"old_text":"enabled = False","new_text":"enabled = True"}
  ]
}
```

每个 old_text 默认必须唯一，所有条目在原始内容上定位，彼此不能重叠。全部校验通过才提交一次。只使用足够定位的短锚点，不要把相距很远的修改拼成大段原文。

需要全局替换时显式声明，可同时限制预期数量：

```json
{
  "path":"src/example.py",
  "old_text":"old_name",
  "new_text":"new_name",
  "replace_all":true,
  "expected_count":4
}
```

批量调用把 replace_all/expected_count 放在相应条目内。不要混用顶层单次参数和批量参数。删除使用显式 `new_text: ""`；遗漏该字段会报错。

## 性能改进

- 共享有界快照缓存，命中前检查文件身份、大小、时间及模式；连续编辑不再重复打开、读取、解码整份源文件。每个 Agent 的已读版本仍独立保存。
- 单行锚点直接搜索原文；统一 CRLF 文件仅转换小锚点；只有混合换行的多行匹配需要建立偏移映射。
- 发现第二个匹配即报告歧义，避免为普通局部编辑枚举所有命中。
- 无变化编辑不编码、写盘或生成 diff，也不会触发修改验证提醒。
- 根据替换位置构造局部 diff；小窗口做精确行比较，大范围改写使用线性、有界预览，避免全文件二次比较和海量行对象。
- GUI 不再前后各读一次文件，也不再根据英语成功文案解析路径；直接消费提交时生成的局部 diff，前端复用这些结果。
- 按行读取降低模型上下文消耗。保持 `max_chars=300000`，图片/文档读取仍走原多模态/提取路径。首次文本读取会建立完整、受大小限制的快照，后续窗口可复用缓存。
- 高频调用不同文件或不同参数不再仅因工具名重复而被误判为循环；成功状态不再被文件名中的 Error/Failed 干扰。

## 本机性能记录

Windows、Python 3.12、本地临时 CRLF 文件。每组先预热 4 对，再交替执行升级前后各 25 次，报告中位数；不包含模型推理和网络。升级前使用本次改造前保存的真实 tools.py。GUI 场景包括正确生成 diff 所需的前后读取、差异计算和 JSON 序列化，不利用旧版批量路径解析错误跳过 diff 来计时。

| 文件大小 | 场景 | 升级前 | 升级后 | 加速比 |
| --- | --- | ---: | ---: | ---: |
| 85 KB | 2 处批量编辑 | 72.21 ms | 79.43 ms | 0.91× |
| 85 KB | GUI 单处编辑 | 68.27 ms | 69.00 ms | 0.99× |
| 85 KB | 无变化编辑 | 59.81 ms | 0.95 ms | 63.09× |
| 1.02 MB | 12 处批量编辑 | 32.03 ms | 31.51 ms | 1.02× |
| 1.02 MB | GUI 单处编辑 | 56.91 ms | 22.08 ms | 2.58× |
| 1.02 MB | 无变化编辑 | 15.89 ms | 0.80 ms | 19.93× |
| 5.10 MB | 12 处批量编辑 | 104.69 ms | 80.31 ms | 1.30× |
| 5.10 MB | GUI 单处编辑 | 248.90 ms | 36.79 ms | 6.77× |
| 5.10 MB | 无变化编辑 | 48.77 ms | 2.12 ms | 22.99× |

GUI 单处编辑的 diff 元数据由约 2.04 MB / 10.20 MB 降至约 0.7 KB。结果大小随实际修改范围增长，上限由预览预算约束。

同一份 1.02 MB 文本，旧默认读取返回 300036 个字符；指定目标窗口 100 行后返回 8523 个字符，减少约 97.2%。这是返回文本量对比，不是模型 token 或推理延迟测量。

小文件纯写入并非每次更快：原子替换、同步和保护检查存在固定成本，Windows I/O 耗时也有明显波动。这里的收益主要是大文件批量编辑、编辑与展示的完整链路、无变化调用和模型读取量；不能把表格解读为所有机器、所有工作负载都同比提速。

## 正确性与兼容变化

- 默认从“全部替换、事后警告”改成“唯一匹配”；旧全局替换调用须加 replace_all。
- 换行匹配兼容 LF/CRLF，替换写入保留 BOM、未修改区域及末尾换行；不自动转换引号、Unicode 或缩进。全文 write 的 content 仍是显式完整文件内容，局部修改应使用 replace。
- Agent/子 Agent/群组会话内，编辑已有文件必须先用对应读取工具读取。成功创建/修改会自动更新版本；恢复会话不会信任历史摘要中的文件版本。
- 直接 Python 调用保留原参数形态，但现在返回 ToolResult：用 `str(result)` 取文案，`result.is_error` 判断成败，`result.display` 取差异和版本。无 Agent scope 的直接调用检查操作期间的文件变化；需要读后冲突保护时传 expected_revision，或使用 FileEditSession/file_edit_scope。
- tool_write_file 和群组产物写入也走共享提交路径，不能用于绕过已读版本冲突。
- GUI 展示提交时的差异。连续修改同一文件时，汇总显示累计编辑行数并保留每次 diff；旧会话的完整前后快照仍按原方式展示净差异。
- ToolResult 增加可选 is_error，旧文本工具保持兼容。该状态同步到 hooks、日志和循环/失败检测，diff 元数据不会发给模型。

## 错误恢复

| 错误码 | 后续动作 |
| --- | --- |
| FILE_NOT_READ | 用 tool_read_file / group_read_workspace 读取目标窗口 |
| FILE_CHANGED | 文件已变化；重新读取、重新判断修改，不能直接覆盖 |
| AMBIGUOUS_MATCH | 根据返回的候选行增加锚点上下文，或显式全局替换 |
| TEXT_NOT_FOUND | 重新读取目标文本，使用实际原文 |
| MATCH_COUNT / OVERLAPPING_EDITS | 修正数量或合并重叠修改；本次没有提交 |
| INVALID_ARGUMENT | 修正参数；new_text 不能遗漏 |
| FILE_BUSY / CANCELLED | 等待中的修改未提交；查看任务状态后决定是否重试 |
| PERMISSION_DENIED / WRITE_FAILED | 提交前失败不会截断原文件；排查占用、权限、磁盘错误 |
| FILE_TOO_LARGE / EDIT_LIMIT / NOT_TEXT / HARD_LINK | 收窄任务或使用明确适用的处理方式 |

## 提交与资源边界

单文件完整写入同目录临时文件、同步并关闭后发布。Windows 使用 ReplaceFileW 并保护原 DACL，支持 Unicode/长路径；POSIX 使用原子替换并保留原模式。新建使用原子“不覆盖已存在目标”的发布方式。链接文件保留符号链接、修改真实目标；多硬链接文件明确拒绝。提交前取消不修改目标；提交后取消、临时文件清理失败不把已完成的修改报告为失败。

文件锁协调同一后端进程中的编辑器调用；修改前和提交前检查版本/元数据。外部编辑器、shell 写入或其他后端进程不受此锁控制，最后一次检查与替换之间仍有竞争窗口；元数据缓存也不以抵御刻意保留时间戳的外部修改为目标。这不是跨进程或多文件事务。未运行本机 POSIX 分支，当前实测环境为 Windows。

- 单个 UTF-8 文本文件/结果：16 MiB。
- 单批最多 256 个条目、10000 个匹配。
- 全局快照缓存：保守内存权重最多 32 MiB、最多 128 个文件；大于缓存预算的文件仍可读取和编辑。
- 每 Agent 最多 4096 个观察版本，淘汰后重新读取。
- diff 最多 40000 个文本字符、1000 行；超出显示截断提示。大型整块改写的行数统计按替换窗口计算，不保证是数学上的最小 diff。
- 等待同文件锁最多 30 秒且可取消；Windows 占用重试最多 0.5 秒。

核心回归包括匹配/批量原子性、LF/CRLF/混合换行/BOM、中文及长路径、版本冲突、并发编辑、取消、写入失败、只读/硬链接、缓存、资源上限、主 Agent 和群组调用；GUI 验证结构化事件、连续编辑历史、旧快照兼容和直接渲染预生成差异。

最终验证：核心全量 240 项通过；GUI 后端文件编辑事件、附件、停止操作相关 13 项通过；前端 diff、文件历史、事件相关 13 项通过；`npm run build` 成功（保留现有大 chunk 提示）。一次并行构建期间，原命令运行测试的 0.4 秒启动窗口超时；单独复跑及最后的核心全量均通过，未修改命令执行逻辑来掩盖该时间敏感性。

界面源文件位于当前被根仓库忽略的 funGUI 目录，本次修改在本地工作区及构建产物中。发布时需一并包含 GUI 与后端；已有进程须重启，已打包版本须重新打包。
