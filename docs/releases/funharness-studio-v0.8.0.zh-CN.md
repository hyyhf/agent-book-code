# FunHarness Studio v0.8.0

FunHarness Studio v0.8.0 重点解决长时间运行、长 reasoning、密集工具调用和工作区预览场景下的内存持续增长问题，并改善 Agent 并发执行、流式连接稳定性以及概念工坊在 Windows 打包版中的资源显示。

## 主要改进

### 内存稳定性

- 优化长 reasoning 与工具参数的流式事件存储，避免随着内容增长反复复制完整历史数据。
- 降低超长对话、密集工具调用和 Markdown/代码高亮场景中的渲染进程内存压力。
- 收起右侧工作区时真正卸载文件预览，不再只通过 CSS 隐藏。
- HTML/PDF 预览关闭时主动释放 iframe、动画、Canvas 和 WebGL 资源。
- 代码预览组件改为按需加载；没有打开代码文件时，不再提前加载 CodeMirror 及语言解析器。
- 新建会话时清理旧预览和工作区状态，并阻止旧会话中已排队的流式事件写入新会话。

### Agent 稳定性与交互

- 改进模型流式连接意外中断时的恢复能力，减少任务无报错提前停止的情况。
- 保留自动重连等有实际意义的状态信息。
- 移除冗余的“正在等待模型响应（第 X 轮）”状态卡片。
- 其他工具调用、执行状态、reasoning 和错误提示保持不变。
- 保留实时流式 Markdown、代码高亮和 reasoning 显示，没有降级为纯文本流式输出。

### 概念工坊资源

- 修复 `concept-growth` 成长路径图片在 Windows 打包版中的路径解析问题。
- 修复 `concept-sprint` 跑道、检查点、角色和终点图片的显示问题。
- 修复 `concept_icon.png` 及概念工坊机器人头像的显示问题。
- 静态资源保存在 Electron 的 `app.asar` 应用归档中，没有转换为 DLL。

## 验证结果

- 真实长会话回放：约 26 万字符、2,607 个流式事件，平均约 74 FPS。
- 工作区与新会话连续循环测试中，工作区、iframe 和旧 reasoning DOM 均能正确卸载，内存进入稳定平台期。
- 概念工坊目标图片已从最终 `app.asar` 中逐项提取，并与源码资源比较 SHA-256，内容完全一致。
- 最终 Windows 免安装版已实际启动，内置后端健康检查通过。
- Agent 循环测试、静态资源相关测试、TypeScript 类型检查和生产构建均通过。

升级前请先退出正在运行的 FunHarness Studio。安装版和免安装版会读取相同的用户配置与工作区数据，请勿同时运行两个版本。

## 说明

- Chromium/V8 会保留一部分已经申请的内存供后续复用，因此任务管理器中的数值不一定在任务结束后立即回到启动值。修复后的判断标准是相同任务重复运行时内存趋于平台，而不是每轮持续增加数百 MB。
- 开发模式包含 React 开发运行时、Strict Mode 检查、Vite HMR 和调试元数据，内存通常高于打包后的生产版本，这是预期差异。
- 本次更新没有缩短上下文长度，没有修改 reasoning 强度，也没有截断模型输出。
